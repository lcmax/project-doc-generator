# Document Templates (Extended · 17-Doc Chapter Skeleton)

> **Localization Standard Note**  
> The English chapter skeletons here align with **IEEE 830 / 1016 / 1471 / 829 / ISO-IEC 25010**. Chapter naming and ordering follow the corresponding IEEE/ISO clauses for each document type.

> **Author Acquisition Priority**  
> When generating documents, the author field is populated based on the following priority:  
> 1. **Current User**: The user invoking the Skill (`$env:USERNAME` / `whoami`)  
> 2. **Git Commit Author**: The latest commit author from the target project (`git log -1 --format=%an`)  
> 3. **Leave Empty**: If neither can be obtained

> **Version Diff Log**  
> When historical document versions exist, the Skill automatically appends a diff log section at the end of each new document:  
> - 🟢 **Added**: Content present in the new document but not in the old  
> - 🟡 **Modified**: Content present in both but changed  
> - 🔴 **Removed**: Content present in the old but removed from the new  
> If no differences, it notes "No changes from previous version"; if entirely new, it is marked as "New document".

> **DOCX Output Format**  
> By default documents are Markdown (`.md`). When the prompt contains `docx`, `word`, or `.docx` (case-insensitive), `.docx` is generated by first producing Markdown then converting via `pandoc`; if pandoc is missing it falls back to Markdown and suggests `winget install JohnMacFarlane.Pandoc`.

> **Version Reference**  
> Version-generation rules see `references/en/git-version-info.md`: with Git `1.{yy}.{Mdd}.{git commit count}`; without Git `1.{yy}.{Mdd}.{hmm}`.
